# Инструкции по площадкам

Один файл — одна площадка. Отсюда берут тексты и мастер первой настройки, и страницы
`/instrukcii/<id>`: править нужно только здесь, разойтись они не могут.

Чтобы заполнить площадку: вписать шаги в `from_platform.steps` и `to_platform.steps`,
положить скриншоты в `static/img/platforms/` и указать их имена, убрать `draft: true`.
Без `draft` страница `/instrukcii/<id>` открывается поиску и попадает в `sitemap.xml`.

| Поле | Что это |
|---|---|
| `id` | адрес страницы и ключ площадки; имя файла — `<id>.yml` |
| `order` | порядок плиток в мастере |
| `name` | название, как его видит хозяин |
| `cabinet` | «в кабинете …» — название в родительном падеже |
| `letter`, `color` | плитка в мастере и цвет броней в шахматке (цвет — из `ChannelPalette`) |
| `logo` | файл логотипа в `static/img/platforms/`; пусто — плитка с буквой |
| `domains` | по ним распознаётся, с какой площадки вставленная ссылка |
| `domains_draft` | `true` — домены не проверены на настоящих ссылках |
| `draft` | `true` — путь по кабинету не проверен: мастер показывает общий текст, страница закрыта от поиска |
| `from_platform` | «Ссылка с площадки»: где её взять. `steps` — по шагу в строке, `screenshot` — файл |
| `to_platform` | «Ссылка для площадки»: куда её вставить |
| `refresh` | как быстро площадка забирает нашу ссылку, словами для хозяина |
| `notes` | особенности площадки, проверенные на практике |

В текстах — слова хозяина: «ссылка с площадки», «ссылка для площадки», «площадка»,
«синхронизация». Технических названий формата и направлений не писать: это проверяет тест
(`PlatformGuidesTest`).
